Project Overview

プロジェクト概要

開発背景・目的

  • IT職種と技術のつながりを可視化
    職種名だけでは分かりにくい「どの言語がどの仕事で使われるか」を相互リンクで整理しました。
  • Java Webの基本構造を実装
    Servlet / JSP / JDBCを使い、リクエスト処理からDBアクセス、画面表示までを自分で構成しました。
  • 一般ユーザーと管理者を分離
    閲覧・質問を行うユーザーと、情報更新・回答を行う管理者の役割を分けました。

Architecture

システム構成

ブラウザからのリクエストをControllerが受け、Command・DAOを経由してOracleと連携します。

Browser / JSP画面表示、フォーム入力、Ajaxリクエスト

画面表示： forward ／ 登録・更新・削除後： redirect ／ 非同期処理： JSONレスポンス

Core Feature 01

職種 ⇄ プログラミング言語 探索

DevNaviの中心となる情報探索機能です。

職種一覧・詳細
8種類のIT職種から詳細を確認し、その職種で使われる言語へ移動できます。
言語一覧・詳細
8種類の言語の特徴や利用分野を確認し、その言語を使う関連職種へ逆方向に移動できます。
DB連携
職種・言語の説明と関連情報をOracleから取得し、JSPへ動的に表示します。
管理者編集
管理者が説明内容を修正するとDBに保存され、サイト表示にも反映されます。

Core Feature 02

会員登録・ログイン

入力検証、重複確認、パスワード保護、セッション管理を実装しました。

ID・ニックネーム重複確認
AjaxでDBを照会し、画面遷移なしで利用可否を確認します。
入力ルール
IDは半角英数字4〜20文字、パスワードは英字と数字を含む8〜20文字で検証します。
BCrypt
パスワードを平文で保存せず、BCryptでハッシュ化して保存・照合します。
Session / Role
ログイン情報をSessionで管理し、USERとADMINで利用できる機能を分けています。

Core Feature 03

コメント・質問・管理者返信

一般会員と管理者の役割を分けたコミュニケーション機能です。

会員コメント
ログイン会員は職種・言語の詳細ページに質問やコメントを登録できます。
本人削除
一般会員は自分が登録したコメントのみ削除できます。
管理者通知
新しいコメント・質問が登録されると管理者ヘッダーの通知件数に反映されます。
1段階返信
管理者だけが会員コメントに返信でき、返信への再返信は作らないシンプルな構造です。

Core Feature 04

問い合わせ・管理者機能

一般会員と管理者の権限を分け、問い合わせの登録から回答・状態管理まで実装しました。

本人の問い合わせのみ閲覧
一般会員は、自分が登録した問い合わせのみ閲覧できます。
問い合わせ登録
一般会員は、タイトルと内容を入力して管理者へ問い合わせできます。
管理者による回答・削除
管理者は会員からの問い合わせを確認し、回答または削除できます。
問い合わせ状態管理
管理者が回答を登録すると、状態が「WAITING」から「ANSWERED」に変更され、回答日時も記録されます。

Implementation & Troubleshooting

実装ポイント・トラブルシューティング

機能を追加するだけでなく、実装中に発生した問題を原因まで確認して修正しました。

認証・会員設計

課題
重複IDや平文パスワードを防ぎ、安全なログイン処理が必要。
対応
Ajax重複確認、サーバー側再検証、BCrypt照合を組み合わせました。
学習
画面側の検証だけではなく、サーバー側でも条件を保証する重要性を学びました。

権限・管理者機能

課題
一般会員と管理者で同じデータを扱いながら操作範囲を分ける必要があった。
対応
MEMBER.ROLEとSession情報を基準に表示・処理を分離しました。
学習
UIでボタンを隠すだけでなく、サーバー処理側でも権限確認が必要だと理解しました。
Future Plan

今後の改善

今回の実装を基礎に、次の学習段階で改善したい内容です。

Spring BootServlet / JSPで理解したMVCとリクエスト処理をSpring MVCへ移行する。
PersistenceJDBC中心のDAOをMyBatisまたはJPAへ置き換え、データアクセス層を改善する。
UI / UX検索・フィルターやモバイル表示を改善し、情報探索をさらに分かりやすくする。
Deploymentローカル環境だけでなく、外部から確認できるデプロイ環境を構築する。
